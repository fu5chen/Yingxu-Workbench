# 部署到自己的服务器

本仓库提供通用源码，没有原部署的 IP、SSH 凭据、证书或私有云资源标识。可以在 Windows 或 Linux 主机运行，不要求购买特定云厂商的服务器。

## 运行服务

1. 安装 Node.js 22.13+（推荐 24）、npm、Git；按需安装 FFmpeg。
2. 在自己的应用目录克隆仓库，执行 README 中的安装、`setup` 和配置步骤。
3. 在进程管理器中运行 `npm run start:local`，工作目录设为项目根目录。进程管理器负责开机启动和退出后的恢复。
4. 为该进程运行账号配置应用目录读写权限，限制其他账号读取私有配置。

首次初始化会创建 `.sites-runtime/external-access/登录信息.json`，其中是随机生成的管理员登录信息。修改账号密码后重新启动，让配置准备脚本更新密码哈希。每个部署应生成自己的凭据。

## 固定域名与 HTTPS

- 将自己的域名 DNS 指向服务器。
- 在 Nginx、Caddy 等反向代理配置有效的 TLS 证书。
- 将 `.sites-runtime/external-access/origin.txt` 内容设为实际访问源，例如 `https://studio.example.com`，不要带路径或末尾斜线。
- 将外网请求转发到 **127.0.0.1:5191** 的登录网关，并保留原始 Host。参考 `config/nginx.example.conf`。
- 仅对外开放 HTTPS 端口，5181 / 5191 保持回环监听。网关使用 Secure Cookie，公网需通过 HTTPS 登录。

**不要将外网直接转发到 5181**。该端口含后台内部接口，只适合可信本机访问。`npm run dev` 同样不能直接暴露到公网。

网关验证 Host、Origin 和会话；更换访问域名时同步修改 `origin.txt`。未正确配置时可能返回“访问地址无效”或跨站错误。

## 临时隧道（Windows，可选）

仓库保留 `scripts/start-external.ps1`。先完成 `npm run setup`，再自行安装 cloudflared，将官方可执行文件放在 `tools/cloudflared.exe` 后运行此脚本。二进制文件不随源码发布。

临时隧道分配的域名可能随重启变化。稳定部署应使用自己的域名和 HTTPS 反向代理；临时隧道地址不适合作为长期素材地址交付客户。

## 更新和备份

维护前确认没有正在提交的生成请求。停止进程，保留私有配置和数据库 / 素材，更新源码后执行 `npm run setup`，再重启并检查登录、列表和后台队列。

不要删除 `.wrangler/state`、正在使用的 `.env` 或存储对象来清理旧发布。`.env` 中的加密密钥需要随数据库一起备份。代码与这些数据分开管理，并制定磁盘、日志、对象存储生命周期策略。
